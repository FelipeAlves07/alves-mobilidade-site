1. VISÃO GERAL DO PROJETO
================================================================================

O projeto AME (Alves Mobilidade Executiva) é composto por TRÊS sistemas
integrados em um único repositório:

  A) SITE INSTITUCIONAL (Público)
     - Páginas: Home, Serviços, Frota, Corporativo, Contato, Quem Somos,
       Solicitar Atendimento (Orçamento)
     - Função: Apresentação da empresa, captação de leads, SEO
     - Design: Dark theme premium com acento azul (#2d6da8)

  B) AME CONTROL (Painel Administrativo)
     - Single Page Application (SPA) em /admin
     - 13 módulos de gestão empresarial
     - Controle remoto do AME Vision (tablet)

  C) AME VISION (Sistema de Bordo para Tablets)
     - Aplicação HTML/CSS/JS standalone (executada em iframe)
     - Exibida em tablets nos veículos durante as viagens
     - Reprodução automática de conteúdo (informação + entretenimento + AME)
     - Mapa ao vivo com GPS, notícias, clima, frota, avaliações

2.2 Fluxo de Dados (Padrão Repository)
───────────────────────────────────────

  AdminPage (SPA)
    └─ useData() ── hook orquestrador
         ├─ useLeads() → createRepository() → SupabaseRepository | LocalStorageRepository
         ├─ useTrips() → createRepository() → SupabaseRepository | LocalStorageRepository
         ├─ useFinance() → createRepository()
         ├─ useReferrals() → createRepository()
         └─ useProposals() → createRepository()
              │
              └─ Repositório decide:
                   Se NEXT_PUBLIC_SUPABASE_URL existe → usa Supabase
                   Senão → usa localStorage (fallback)

  Os módulos (DashboardView, ClientesView, etc.) recebem dados + callbacks
  como props e chamam as funções do AdminPage (addLead, finishTrip, etc.)

2.3 Fluxo do AME Vision
────────────────────────

  AMEVisionPanel (admin)
    │
    ├─ Polling a cada 3s: readAMEVisionState() ← Supabase (ame_vision_state)
    │
    ├─ writeAMEVisionState() → Supabase (status, trip, started_at)
    │
    └─ postMessage() → iframe (AME Vision)
         │
         └─ VisionPlayer (player.js)
              ├─ applySession() → define estado (idle/prepared/running/completed)
              ├─ applySettings() → durações, modo (longa/curta), GPS, rota
              └─ startSchedule() → roda as 14 telas em sequência
                   │
                   ├─ Tela "live-map": GPS via Leaflet.js + /api/ame-vision/route
                   ├─ Tela "news":     RSS feeds via /api/ame-vision/news
                   └─ Demais telas: conteúdo estático (content.js)

5. AME VISION (Sistema de Bordo)
================================================================================

5.1 O que é
  Sistema de entretenimento e informação veicular executado em tablet
  posicionado no veículo. Reprodução automática de conteúdo em ciclo,
  com menu interativo para o passageiro.

5.2 Programação
  Aproximadamente 70% informação + entretenimento, 30% conteúdo AME.
  Ciclo estimado: ~30 minutos (curta) ou ~60 minutos (longa com descanso).

5.3 As 14 Telas

  ID            | Duração | Grupo          | Descrição
  ──────────────|─────────|────────────────|──────────────────────────────
  welcome       | 18s     | AME            | Boas-vindas com nome do cliente
  trip          | 26s     | Informação     | Rota, motorista, veículo, ETA
  live-map      | 10min   | Descanso/info  | Mapa ao vivo com GPS
  weather       | 24s     | Informação     | Clima da cidade
  news          | ~100s   | Entretenimento | 10 notícias em carrossel
  comfort       | 24s     | Informação     | Dicas de conforto a bordo
  fleet         | 45s     | AME            | Carrossel da frota
  destinations  | 60s     | Entretenimento | Destinos turísticos (MG)
  referral      | 32s     | AME            | Programa de indicação
  reviews       | 28s     | AME            | Avaliações de clientes
  contact       | 32s     | AME            | QR Code WhatsApp + site
  rest          | 10min   | Descanso       | Tela com relógio (modo longa)
  pause-one     | 20s     | Entretenimento | Intervalo visual 1
  pause-two     | 22s     | Entretenimento | Intervalo visual 2

5.4 Estados da Sessão
  - idle:      "Aguardando a próxima viagem"
  - prepared:  "Bem-vindo a bordo" (mostra rota + motorista)
  - running:   Ciclo principal rodando (após 2min da preparação)
  - completed: "Obrigado" → volta a idle após 45s

5.5 Comunicação (postMessage)
  Parent → Iframe:
    - AME_VISION_SETTINGS: durações, modo, GPS, rota
    - AME_VISION_SESSION: estado da sessão
    - AME_VISION_OPEN_SCREEN: abrir tela específica
  Iframe → Parent:
    - AME_VISION_READY: iframe carregado

5.6 API Exclusiva
  - GET /api/ame-vision/route      → Roteirização OSRM
  - GET /api/ame-vision/news       → RSS feeds + proxy de imagens
  - GET /api/ame-vision/news/image → Proxy de imagem

8. SUGESTÕES DE MELHORIAS
================================================================================

8.1 CRÍTICAS / PRIORIDADE ALTA
───────────────────────────────

  [P1] Login do Admin é frágil
       Senha fixa em utils/constants.ts. Qualquer pessoa com acesso ao
       código sabe a senha. Sugestão: usar apenas Supabase Auth com
       magic link ou provedor OAuth. Remover a senha hardcoded.

  [P2] Sem testes automatizados
       Existe vitest configurado mas sem testes. Sugestão: criar testes
       para o motor de precificação (calculateQuoteValue), parser de
       voz (parseVoiceNumbers), e lógica de propostas.

  [P3] Sem tratamento de erro offline
       Se o Supabase cair, o admin perde dados. O LocalStorageRepository
       existe como fallback mas não é usado ativamente. Sugestão:
       implementar sync bidirecional (offline-first) com queue de
       operações pendentes.

8.2 IMPORTANTES
───────────────

  [P4] Imagens não otimizadas
       84 arquivos não utilizados em public/. Imagens grandes sem
       compressão. Sugestão: usar next/image com width/height, remover
       imagens não usadas, converter PNG para WebP/AVIF.

  [P5] AME Vision sem fallback de rede
       O iframe depende de CDNs (Leaflet, Google Fonts). Se o tablet
       estiver sem internet, o mapa não carrega. Sugestão: bundle
       Leaflet localmente, usar Service Worker para cache.

  [P6] Código legado duplicado
       services/*.ts (CRUD direto) coexiste com hooks/*.ts (Repository
       pattern). Sugestão: remover services/*.ts e migrar tudo para o
       padrão Repository.

8.3 MELHORIAS DE UX
───────────────────

  [P7] Feedback visual no Admin
       Operações CRUD não têm toast/notificação. O usuário não sabe
       se salvou. Sugestão: implementar sistema de toasts.

  [P8] Loading states
       Nenhum dos módulos tem skeleton/spinner enquanto carrega dados.
       Sugestão: adicionar Suspense + skeletons.

  [P9] Mobile do Admin
       Sidebar desktop não tem versão mobile adequada (MobileNav existe
       mas é limitado). Sugestão: transformar sidebar em drawer
       deslizante no mobile.

8.4 AME VISION
──────────────

  [P10] Conteúdo do AME Vision
        Clima e notícias dependem de APIs externas. Sugestão: adicionar
        cache mais longo, fallback visual quando offline.

  [P11] Personalização por viagem
        Mensagem de boas-vindas é aleatória (array de 10 frases).
        Sugestão: campo personalizado no formulário de viagem.

  [P12] Analytics do Vision
        Não há logging de quais telas foram exibidas, por quanto tempo,
        etc. Sugestão: enviar telemetria para Supabase (trip_contents).

8.5 NEGÓCIO
───────────

  [P13] Gateway de pagamento
        Sistema não processa pagamentos. Sugestão: integrar Stripe/Pix
        para cobrança automática de viagens.

  [P14] Notificações push
        Clientes não recebem lembretes de viagem. Sugestão: WhatsApp
        API ou email automático 1h antes.

  [P15] Multi-tenant
        Estrutura de companies existe mas não é usada ativamente.
        Sugestão: implementar separação por empresa para franchise.
